# Подтверждённые UX-баги Game Time Tracker

## 1. При обнаружении нового процесса приложение принудительно выходит на передний план

### Проблема

Когда Game Time Tracker находится в свёрнутом/минимизированном состоянии, а пользователь запускает новую программу или игру, трекер обнаруживает новый процесс и **самостоятельно восстанавливает своё окно поверх запущенной программы**.

Это раздражает пользователя: он запускает игру/программу, а вместо продолжения работы внезапно получает окно Game Time Tracker поверх неё.

Дополнительно текущая логика работает некорректно: после восстановления приложение может остаться, например, на вкладке **«Статистика»**, при этом окно добавления новой игры пользователю не показывается.

### Фактическое поведение

1. Game Time Tracker минимизирован.
2. Пользователь запускает новую программу/игру.
3. Tracker обнаруживает новый процесс.
4. Tracker сам появляется поверх запущенной программы.
5. При этом пользователь не получает нормального окна добавления игры.
6. Приложение может остаться на текущей вкладке, например «Статистика».

### Ожидаемое поведение

Обнаружение нового процесса **не должно принудительно восстанавливать главное окно Game Time Tracker**.

Нужна более нормальная схема:

1. Tracker в фоне обнаруживает новый процесс.
2. Показывается обычное системное уведомление о новом обнаруженном процессе.
3. **Только при клике пользователя по этому уведомлению** открывается интерфейс добавления/подтверждения игры.
4. Если пользователь пропустил уведомление, оно должно сохраняться в списке уведомлений внутри приложения.
5. В главном окне желательно иметь иконку колокольчика/уведомлений.
6. В списке уведомлений должна оставаться запись о новом обнаруженном процессе, чтобы пользователь мог позже открыть её и добавить игру.

### Важное ограничение

Нельзя решать проблему простым отключением уведомлений.

Нужно сохранить фоновое обнаружение новых процессов, но убрать принудительный `focus/restore` главного окна.

## 2. Решение «НЕ ОТСЛЕЖИВАТЬ» не сохраняется после перезапуска

### Проблема

Когда пользователь при обнаружении процесса выбирает **«НЕ ОТСЛЕЖИВАТЬ»**, Tracker перестаёт предлагать отслеживать этот процесс.

Однако это состояние хранится только в памяти приложения.

После полного перезапуска Game Time Tracker информация о том, что пользователь ранее отказался отслеживать этот процесс, теряется.

### Фактическое поведение

1. Запускается неизвестная программа.
2. Tracker предлагает добавить её в отслеживание.
3. Пользователь выбирает **«НЕ ОТСЛЕЖИВАТЬ»**.
4. Пока Tracker работает, этот процесс больше не беспокоит пользователя.
5. Tracker закрывается и запускается снова.
6. При следующем обнаружении того же процесса Tracker снова считает его новым и предлагает добавить его.

### Ожидаемое поведение

Решение **«НЕ ОТСЛЕЖИВАТЬ» должно сохраняться в базе данных/настройках**.

После перезапуска приложения Tracker должен помнить этот выбор и не предлагать отслеживать такой процесс снова.

### Дополнительное UX-требование

Желательно добавить в интерфейс раздел/меню вроде:

**«Не отслеживаются»**

В нём пользователь должен видеть процессы, для которых ранее выбрал «НЕ ОТСЛЕЖИВАТЬ», и иметь возможность отменить это решение.

Например:

> Не отслеживаются
> • chrome.exe
> • Discord.exe
> • Telegram.exe
>
> [Разрешить отслеживание]

Это позволит пользователю вернуть процесс в список отслеживаемых, если он передумает.

## 3. Переименование игры не обновляет фильтр поиска

### Проблема

Если пользователь выполняет поиск по названию игры, а затем переименовывает найденную игру так, что новое название **больше не соответствует поисковому запросу**, карточка всё равно остаётся отображаться.

### Фактический пример

1. В поиске введено:
   `Witcher`
2. В списке отображается игра **The Witcher 3**.
3. Пользователь переименовывает её в:
   `Cyberpunk 2077`
4. Поисковый запрос `Witcher` остаётся активным.
5. Карточка **Cyberpunk 2077 продолжает отображаться**, хотя она больше не соответствует фильтру.

### Ожидаемое поведение

После переименования игры текущий поисковый фильтр должен применяться повторно.

В приведённом примере после переименования:

> Поиск: `Witcher`

карточка `Cyberpunk 2077` должна исчезнуть из результатов поиска.

Если новое название соответствует поисковому запросу, карточка, наоборот, должна остаться.

### Приоритет

Баг подтверждён, но **низкоприоритетный**, поскольку такая последовательность действий встречается нечасто.

Тем не менее исправление небольшое и логически необходимо: после изменения названия карточки состояние списка должно соответствовать текущему поисковому запросу.

## 4. Поиск визуально остаётся активным, но после обновления показывает все игры

### Проблема

Если пользователь ввёл поисковый запрос во вкладке **«Мои игры»**, а затем выполняется действие, которое вызывает обновление списка игр, карточки пересоздаются заново, но текущий поисковый фильтр к ним повторно не применяется.

При этом текст в поле поиска **остаётся**.

В результате интерфейс находится в противоречивом состоянии:

> В поле поиска написано `Witcher`, но отображаются все игры.

### Как воспроизвести

1. Открыть вкладку **«Мои игры»**.
2. Ввести в поиск название, например:
   `Witcher`
3. Убедиться, что отображаются только соответствующие игры.
4. Изменить сортировку списка, например с **«По времени»** на **«По дате добавления»**.
5. После обновления списка посмотреть на поле поиска.

### Фактическое поведение

Поле поиска продолжает содержать:

`Witcher`

но список снова показывает **все игры**, в том числе те, которые не соответствуют поисковому запросу.

### Причина в коде

`refresh_games()` полностью уничтожает существующие карточки:

```python
for widget in self.scrollable_frame.winfo_children():
    widget.destroy()
```

и создаёт их заново.

При этом:

* `search_var` не очищается;
* `filter_games()` после `refresh_games()` не вызывается.

Поэтому новое содержимое списка не проходит через текущий поисковый фильтр.

### Где ещё может проявляться (необходимо проверить)

Проблема относится не только к изменению сортировки.

Она может проявляться после любых действий, вызывающих `refresh_games()`, например:

* добавление игры;
* архивирование игры;
* удаление игры;
* изменение сортировки;
* другие операции, после которых список игр пересоздаётся.

### Ожидаемое поведение

Текущий поисковый запрос должен сохраняться при обновлении списка и **автоматически применяться к новым карточкам**.

Например:

`Поиск: Witcher`

→ пользователь меняет сортировку

→ список обновляется

→ по-прежнему отображаются только игры, соответствующие `Witcher`.

Если поисковая строка пустая, должны отображаться все игры.

### Важное требование к исправлению

Не нужно очищать поисковую строку при `refresh_games()`.

Нужно сохранить текущее значение поиска и после пересоздания карточек повторно применить фильтр.

**Статус: подтверждённый UX-баг.**

## 5. Отдельная доработка — переключатель «Учитывать архив» в статистике

Добавить в разделе «Статистика» переключатель **«Учитывать архив»**.

**По умолчанию:** выключен.

* **Выключен** — статистика считается только по активным играм из раздела «Мои игры».
* **Включен** — в статистику дополнительно включаются игры из «Архива».

Переключатель должен влиять на **всю статистику**, а не только на отдельный показатель:

* общее игровое время;
* количество игр/сессий;
* топ игр;
* график игровой активности;
* среднюю продолжительность сессии;
* лучший игровой день;
* самую длинную сессию;
* остальные показатели, которые рассчитываются на основании игровых сессий.

При переключении статистика должна **сразу пересчитываться и обновляться**, без необходимости перезапускать приложение.

Важно: это именно переключатель режима расчёта статистики, а не изменение состояния игр. Включение «Учитывать архив» не должно возвращать игры из архива в «Мои игры» и не должно менять их статус.
