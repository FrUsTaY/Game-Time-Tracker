## 🛠 Подробное описание задач

### Задача 1: Защита от краша при `duration_seconds = NULL` (TypeError)
* **Приоритет:** 🚨 Критический
* **Файлы:** `ui/tab_stats.py` (строки ~210–215), `ui/tab_calendar.py` (строки ~148–155)
* **Проблема:**
  1. В SQLite поле `duration_seconds` в таблице `sessions` может содержать `NULL` (например, при некорректно завершённых сессиях, прямом редактировании БД или при незаполненных данных).
  2. Запрос `get_sessions_range` возвращает строки в виде словарей: `{'duration_seconds': None}`.
  3. Конструкция `duration = sess.get('duration_seconds', 0)` возвращает `None`, так как ключ `'duration_seconds'` в словаре существует.
  4. Последующие сравнения `if duration > 0` в `TabStats` и `if duration <= 0` в `TabCalendar` вызывают фатальную ошибку:
     `TypeError: '>' not supported between instances of 'NoneType' and 'int'`, из-за чего вкладки полностью перестают открываться и отрисовываться.
* **Что сделать:**
  1. Использовать безопасное извлечение значения длительности: `duration = sess.get('duration_seconds') or 0`.
  2. Добавить юнит-тесты с сессиями, содержащими `duration_seconds = None`, проверяющие корректную отрисовку без исключений.
* **Проверка:** Запустить `python -m unittest discover -s tests` — убедиться, что тесты успешно обрабатывают сессии с `None`.

### Задача 2: Интеллектуальная фильтрация уведомлений «Обнаружена новая игра»
* **Приоритет:** 🚨 Критический
* **Файл:** `tracker.py` (строки ~127–146)
* **Проблема:**
  1. Метод `_check_processes()` отправляет уведомление `Обнаружена новая игра: <exe_name>` для любого процесса из `running_processes.keys()`, которого ещё нет в библиотеке.
  2. В Windows постоянно запускаются системные и фоновые процессы (`smartscreen.exe`, `SearchFilterHost.exe`, `git.exe`, `conhost.exe`, службы обновления). Пользователь получает непрерывный спам ложными уведомлениями о системных утилитах как о «новых играх».
* **Что сделать:**
  1. Отправлять уведомление о новой игре только для процессов, имеющих **видимое окно верхнего уровня** (`IsWindowVisible`), то есть являющихся графическими приложениями.
  2. Игнорировать процессы, исполняемые файлы которых находятся в системных папках Windows (`C:\Windows\...`, `System32`, `SysWOW64`).
  3. Добавить список общеизвестных системных исключений (например, `explorer.exe`, `taskmgr.exe`, `cmd.exe`, `powershell.exe`, `conhost.exe`).
* **Проверка:** Запустить в фоновом режиме консольные команды или системные службы — убедиться, что ложные уведомления не приходят, а при запуске реальной игры с окном уведомление корректно появляется.

### Задача 3: Учёт времени архивированных игр в общей статистике
* **Приоритет:** ⚠️ Высокий
* **Файл:** `ui/tab_stats.py` (строки ~138–147)
* **Проблема:**
  1. В карточке «Всего часов» на вкладке «Статистика» суммируется время только активных игр: `games = self.db.get_all_games(archived=False)`.
  2. Когда игрок проходит игру (например, потратив 100 часов) и отправляет её в «Архив», общее наигранное время в приложении уменьшается на 100 часов.
  3. При этом на вкладке «Календарь» это время продолжает отображаться, что сбивает пользователя с толку и ломает логику накопления игрового опыта.
* **Что сделать:**
  1. В методе `_update_summary_cards()` суммировать время по всем играм: `all_games = games + archived_games`, `total_seconds = sum(g['total_seconds'] for g in all_games)`.
  2. При желании в карточке отображать детализацию: например, `120.5 ч (в архиве: 100 ч)`.
* **Проверка:** Добавить игру, наиграть время, перенести в архив — проверить вкладку «Статистика»: счётчик «Всего часов» не должен уменьшаться.

### Задача 4: Синхронизация автозапуска с кнопками окна настроек
* **Приоритет:** ⚠️ Средний
* **Файл:** `ui/settings_window.py` (строки ~45–51, ~183–200)
* **Проблема:**
  1. Переключатель «Запускать вместе с Windows» вызывает метод `_on_autostart_toggle()` сразу при клике, немедленно изменяя ключ в реестре Windows (`HKCU\...\Run`) и значение в базе данных.
  2. Если пользователь изменил переключатель автозапуска, а затем нажал «Отмена», изменение в реестре сохраняется, в то время как все остальные настройки отменяются.
* **Что сделать:**
  1. Убрать мгновенный вызов `enable_autostart()` / `disable_autostart()` по клику на переключатель. Хранить промежуточное состояние в `self.vars["autostart"]`.
  2. Применять изменение автозапуска исключительно в методе `save_and_close()` при нажатии кнопки «Сохранить и закрыть».
* **Проверка:** Открыть настройки, переключить автозапуск, нажать «Отмена» — состояние автозапуска в реестре не должно измениться. Нажать «Сохранить и закрыть» — изменения должны примениться.

### Задача 5: Улучшение ввода и добавления игр
* **Приоритет:** ⚠️ Средний
* **Файл:** `ui/tab_games.py` (строки ~365–375, ~389–401)
* **Проблема:**
  1. В диалоге «Ввести вручную» пользователь может ввести название файла без расширения (например, `witcher3`). Игра сохраняется в базу как `witcher3`, а `psutil` в Windows всегда возвращает `witcher3.exe`. Из-за несовпадения игра никогда не начнёт отслеживаться.
  2. При пакетном добавлении нескольких процессов из `AddFromProcessesDialog` метод `_add_games_from_processes()` в цикле показывает модальное окно `messagebox.showinfo` на каждую игру и каждый раз полностью перерисовывает карточки игр.
* **Что сделать:**
  1. При ручном вводе нормализовать имя: если оно не заканчивается на `.exe`, автоматически добавлять `.exe`.
  2. При пакетном добавлении из запущенных процессов добавлять все выбранные игры в базу без всплывающих окон на каждый шаг, после чего показать одно итоговое уведомление: «Добавлено игр: N» и один раз вызвать `refresh_games()`.
* **Проверка:** Ввести вручную `skyrim` — проверить, что игра сохранилась как `skyrim.exe` и подхватывается трекером. Выбрать 3 процесса в диалоге — проверить, что появляется только одно итоговое сообщение.

### Задача 6: Оптимизация кэша настроек, сохранение spec-файла и чистота кода
* **Приоритет:** 💡 Оптимизация и чистота кода
* **Файлы:** `settings.py`, `build.py`, `tests/test_database.py`, `ui/tab_games.py`
* **Проблема:**
  1. В `settings.py` словарь `self._cache` наполняется в сеттерах, но игнорируется в `_get_bool()` и `_get_int()`, приводя к 3–4 избыточным SQL-запросам в секунду из потока трекера.
  2. В `build.py` функция `clean_build()` удаляет `GameTimeTracker.spec`, сбрасывая конфигурацию сборки и ломая тест `test_audit2_tasks5_6.py`.
  3. В `tests/test_database.py` на строках 47–48 ошибочно остался вызов `if __name__ == '__main__': unittest.main()`, из-за чего прямой запуск файла выполняет только 1 тест и игнорирует оставшиеся 970 строк тестов.
  4. В `ui/tab_games.py` (строки 311, 332) остались отладочные принты `DEBUG: ...`, спамящие в консоль.
* **Что сделать:**
  1. В `settings.py` проверять кэш перед обращением к БД (`if key in self._cache: return self._cache[key]`).
  2. В `build.py` удалить строку удаления `GameTimeTracker.spec` при очистке.
  3. В `tests/test_database.py` убрать промежуточный блок запуска `unittest.main()` со строки 47.
  4. В `ui/tab_games.py` убрать оставшиеся `print(f"DEBUG: ...")`.
* **Проверка:** Запустить `python tests/test_database.py` — убедиться, что выполняются все тесты файла. Запустить `python -m unittest discover -s tests` — убедиться в успешном прохождении всех тестов без лишнего отладочного спама.
