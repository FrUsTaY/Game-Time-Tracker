### Задача 1: Защита от дубликатов приложения (мьютекс)
* **Приоритет:** 🚨 Критический
* **Файл:** `main.py` (строки ~15–28, 40–44)
* **Проблема:** Переменная `mutex = win32event.CreateMutex(...)` является локальной в функции `is_already_running()`. При выходе из функции Python уничтожает объект (деструктор вызывает `CloseHandle`), и мьютекс исчезает. Второй запущенный экземпляр не видит первого и запускается параллельно, приводя к конфликту доступа к SQLite.
* **Что сделать:**
  1. Вынести хранение дескриптора мьютекса в глобальную переменную модуля (например, `_app_mutex = None`) либо передавать его в объект `App`.
  2. Дескриптор должен оставаться открытым на протяжении всей работы программы и закрываться только перед `sys.exit()`.
* **Проверка:** Запустить приложение дважды подряд. Второй запуск должен выдать предупреждение «Приложение уже запущено» и закрыться.

### Задача 2: Потокобезопасность обновления UI (Tkinter Thread-Safety)
* **Приоритет:** 🚨 Критический
* **Файлы:** `tracker.py` (строки ~156–160, ~250–255), `app.py` (строки ~50–57), `ui/tab_games.py` (строки ~307–339)
* **Проблема:** Фоновый поток трекера `_monitor_loop` напрямую вызывает метод `on_tick()`, который дёргает методы Tkinter-виджетов и `update_idletasks()`. Tkinter не является потокобезопасным: прямые вызовы из стороннего потока приводят к случайным сбоям `Access Violation` в `tk86t.dll` и зависаниям интерфейса.
* **Что сделать:**
  1. В `app.py` обернуть вызов колбэка обновления через планировщик Tkinter:
     ```python
     self.tracker.on_tick = lambda gid, total, active: self.window.after(
         0, lambda: games_tab.update_tick(gid, total, active)
     )
     ```
  2. В `ui/tab_games.py` убрать принудительные вызовы `update_idletasks()` (Tkinter обновит виджеты автоматически в главном цикле событий).
* **Визуальный эффект:** Секунды продолжат плавно тикать в реальном времени, но пропадут микрофризы и риск внезапного вылета программы.

### Задача 3: Потокобезопасность SQLite (`threading.RLock`)
* **Приоритет:** 🚨 Критический
* **Файлы:** `database.py`, `ui/tab_stats.py`, `ui/tab_calendar.py`
* **Проблема:** База открыта с `check_same_thread=False`. Фоновый поток пишет сессии и общее время, а основной поток читает статистику и настройки. При одновременном обращении возникает `sqlite3.OperationalError: database is locked` или повреждение транзакций.
* **Что сделать:**
  1. В `Database.__init__` объявить `self.lock = threading.RLock()`.
  2. Обернуть все публичные методы чтения и записи в `with self.lock:`.
  3. Вкладкам интерфейса запретить напрямую обращаться к `self.db.conn.cursor()` — перенести специфичные SQL-запросы в методы класса `Database` (под защиту блокировки).
* **Проверка:** Запустить автотесты `python -m unittest discover tests` и убедиться в отсутствии дедлоков и ошибок блокировки.

### Задача 4: Устранение утечки ресурсов GDI и дескрипторов Windows
* **Приоритет:** 🚨 Критический
* **Файл:** `tracker.py` (метод `get_exe_icon`, строки ~275–306)
* **Проблема:**
  1. `win32gui.GetDC(0)` захватывает контекст экрана. Вызов `hdc.DeleteDC()` не освобождает его — требуется `win32gui.ReleaseDC(0, hdc_raw)`.
  2. `win32gui.ExtractIconEx(...)` возвращает списки дескрипторов иконок. Уничтожается только один `hicon`, а все остальные остаются висеть в памяти.
  3. Утечка дескрипторов (User/GDI Objects) приводит к падению приложения при достижении системного лимита в 10 000 объектов.
* **Что сделать:**
  1. Корректно закрывать все иконки из списков `large_icons` и `small_icons`, кроме используемой, а саму используемую закрывать в блоке `finally`.
  2. Корректно вызывать `ReleaseDC` и освобождать временный битмап.
* **Проверка:** В диспетчере задач Windows (вкладка «Подробности» -> столбцы «Объекты GDI» и «Объекты USER») добавить много игр и убедиться, что количество дескрипторов стабильно и не растёт бесконечно.

### Задача 5: Защита от потери времени и очистка «зомби-сессий»
* **Приоритет:** 🚨 Критический
* **Файлы:** `tracker.py` (строки ~148–175, ~237–257), `database.py`, `app.py`, `ui/main_window.py`
* **Проблема:**
  1. Время сессии `current_seconds` копится только в оперативной памяти и сбрасывается в БД только при закрытии игры. При краше, отключении питания или зависании игры всё накопленное время теряется.
  2. Если игра была закрыта некорректно, запись в таблице `sessions` остаётся с `ended_at = NULL`.
  3. Кнопка «Выход» в боковом меню `MainWindow` вызывает `sys.exit(0)` вместо штатного `app.exit_app()`, бросая сессии незакрытыми.
* **Что сделать:**
  1. Добавить периодический сброс (`flush`) прогресса: раз в 60 секунд обновлять `total_seconds` в `games` и промежуточный `duration_seconds` в `sessions`.
  2. В `Database.__init__` добавить метод очистки незавершённых сессий прошлых запусков:
     ```sql
     UPDATE sessions
     SET ended_at = started_at, duration_seconds = 0
     WHERE ended_at IS NULL;
     ```
  3. В `MainWindow.quit_app()` вызывать корректный выход приложения через переданный колбэк `on_exit`.
* **Визуальный эффект:** Секунды тикают каждую секунду в реальном времени, но каждые 60 секунд надёжно сохраняются на диск.

### Задача 6: Безопасный бэкап базы данных (Online Backup API)
* **Приоритет:** ⚠️ Высокий
* **Файл:** `ui/settings_window.py` (строки ~213–224)
* **Проблема:** Использование `shutil.copy2` на работающей базе данных во время записи сессий может скопировать файл в момент незавершённой транзакции (corrupted database file).
* **Что сделать:**
  1. Заменить файловое копирование на встроенный механизм онлайн-бэкапа SQLite:
     ```python
     def backup_database(self, target_path: str):
         with self.lock:
             backup_conn = sqlite3.connect(target_path)
             self.conn.backup(backup_conn)
             backup_conn.close()
     ```
* **Проверка:** Создать бэкап во время активного трекинга игры и открыть его любой утилитой (например, DB Browser for SQLite) — файл должен открываться без ошибок целостности.

### Задача 7: Исправление путей для автозагрузки (CWD Vulnerabilities)
* **Приоритет:** ⚠️ Средний
* **Файлы:** `app.py`, `settings.py`, `ui/main_window.py`, `ui/tab_games.py`, `ui/settings_window.py`, `ui/tab_about.py`
* **Проблема:** При запуске через ветку реестра Windows `Run` рабочая директория программы часто равна `C:\Windows\System32`. Из-за относительных путей (`data/icons`, `assets/icon.png`, `main.py`) папки создаются в системном каталоге либо программа падает из-за отсутствия прав доступа.
* **Что сделать:**
  1. Ввести единую утилитную функцию получения базового каталога приложения (`get_base_dir()`).
  2. Все пути (`assets`, `data`, `data/icons`, `data/backups`, путь к `main.py` в реестре) формировать исключительно через `os.path.join(get_base_dir(), ...)`.
* **Проверка:** Запустить скрипт из произвольной папки через консоль (например, находясь в `C:\`): `python C:\...\Game-Time-Tracker\main.py` — все иконки и БД должны создаваться рядом с программой.

### Задача 8: Оптимизация анимации пульсации в `TabAbout`
* **Приоритет:** ⚠️ Средний
* **Файл:** `ui/tab_about.py` (строки ~137–159)
* **Проблема:** Метод `_start_pulse_animation` запускает бесконечный таймер `after(50, ...)`, где 20 раз в секунду пережимает изображение через тяжёлый фильтр `LANCZOS`. Цикл работает даже при скрытой вкладке и в трее, сжигая 5–15% CPU постоянно.
* **Что сделать:**
  1. Предварительно рассчитать (отрендерить) 6–8 кадров анимации один раз при инициализации.
  2. Привязать запуск/остановку цикла к событиям видимости вкладки (`<Visibility>`, `<Unmap>`), либо останавливать таймер, когда вкладка не активна.
* **Проверка:** В диспетчере задач проверить потребление CPU программой в простое — оно должно быть около 0.0–0.1%.

### Задача 9: Устранение утечки памяти при отрисовке Matplotlib
* **Приоритет:** ⚠️ Средний
* **Файл:** `ui/tab_stats.py` (строки ~186–200, ~224–236)
* **Проблема:** При обновлении графиков создаются новые объекты `Figure`, а старые виджеты уничтожаются без вызова `plt.close(fig)` / `fig.clf()`. Объекты графиков накапливаются во внутренних структурах Matplotlib.
* **Что сделать:**
  1. Явно закрывать предыдущую фигуру перед созданием новой (`fig.clear()`, `plt.close(fig)`).
  2. Или сохранить одну фигуру `self.fig` на всё время и просто вызывать `self.ax.clear()` перед повторным рисованием.
* **Проверка:** Переключиться между периодами «7 дней», «30 дней», «90 дней» 50 раз подряд — потребление оперативной памяти не должно расти.

### Задача 10: Индексация БД SQLite
* **Приоритет:** 💡 Оптимизация
* **Файл:** `database.py` (метод `_create_tables`)
* **Проблема:** В таблице `sessions` нет индексов по `started_at` и `game_id`. Со временем запросы календаря и графиков будут делать Full Table Scan.
* **Что сделать:**
  1. Добавить создание индексов:
     ```sql
     CREATE INDEX IF NOT EXISTS idx_sessions_started_at ON sessions (started_at);
     CREATE INDEX IF NOT EXISTS idx_sessions_game_id ON sessions (game_id);
     ```
* **Проверка:** Выполнить `EXPLAIN QUERY PLAN SELECT ...` и убедиться в использовании `SEARCH TABLE sessions USING INDEX`.
