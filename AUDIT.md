# 🔍 Аудит GameTimeTracker v1.2.2 → v1.4.0

Дата: 26.10.2026 · Ветка: `arena/be28a679-game-time-tracker` · Объём: ~8 300 строк Python, 15 файлов тестов

Документ фиксирует результаты технического и продуктового аудита, а также **что уже
исправлено/добавлено в этой ветке**. Всё, что помечено ✅, реализовано и покрыто тестами;
раздел «Что осталось» — приоритизированный бэклог.

## 1. Краткая сводка

| Область | Оценка | Главный риск / вывод |
|---|---|---|
| Архитектура | 🟡 3.5/5 | `Database` — «god object» (~800 строк), но слои разделены аккуратно |
| Надёжность данных | 🟢 4/5 → 4.5/5 | SQLite без WAL и миграций, `last_launched` перезаписывался при сбросе прогресса |

| Диагностируемость | 🔴 2/5 → 🟢 4.5/5 | `print()` в windowed-сборке не виден нигде, журналов не было |

| Сопровождаемость | 🟡 3/5 | Нет `pyproject.toml`, линтера, разделения runtime/build/dev-зависимостей |

**Ключевой вывод:** приложение функционально богатое и заметно «вылизано» по UX, но

функции, повышающие практическую ценность трекера (AFK-пауза, дневной лимит, отчёты,
краткосрочная аналитика).

## 2. Найденные проблемы и что сделано

### P0 — потеря данных / невозможность диагностики

**2.1. `print()` вместо журналирования** ✅ исправлено
В сборке PyInstaller `--windowed` нет консоли: все сообщения трекера, БД и трея писались
«в никуда». При зависании или сбое фонового потока причину установить было невозможно.
*Решение:* модуль `logging_setup.py` — файловый журнал с ротацией
(`data/logs/gametimetracker.log`, 1 МБ × 3), запись в stderr при запуске из исходников.
Ошибки ключевых модулей переведены на `logger`.

**2.2. Отсутствие миграций схемы БД** ✅ исправлено
`CREATE TABLE IF NOT EXISTS` не добавляет новые колонки в существующие таблицы. Любое
будущее изменение схемы (`games.launch_count`, `sessions.duration_seconds`) ломало бы
старые базы ошибкой `no such column`.
*Решение:* `PRAGMA user_version` + `SCHEMA_VERSION = 2`, идемпотентные
`_ensure_column()`-миграции, отдельное создание индексов после миграции, тест на «старую» БД.

**2.3. SQLite без WAL и `busy_timeout`** ✅ исправлено
UI-поток и поток трекера работают с одним соединением; при записи возможны были
`database is locked` и микрозамирания интерфейса. `RLock` защищал только внутри процесса.
*Решение:* `journal_mode=WAL`, `busy_timeout=5000`, `synchronous=NORMAL` (для файловых БД),
плюс индексы `idx_sessions_ended_at`, `idx_games_is_archived`.

**2.4. Риск взаимной блокировки в трекере** ✅ исправлено
`_check_processes()` держит `self.lock` и вызывает `_close_session()`/`get_live_today_seconds()`,
которые тоже пытаются взять тот же `threading.Lock` → потенциальный дедлок.
*Решение:* `RLock` + явная проверка лимита вне критической секции по смыслу.

### P1 — некорректная статистика

**2.5. Сессии, пересекающие полночь, относились к дню старта** ✅ исправлено
`get_sessions_by_date()`/`get_sessions_range()` фильтровали по `started_at`, а календарь и
график активности целиком записывали такую сессию в день старта. Пример: игра с 23:30 до
01:15 давала 1 ч 45 мин «вчера» и 0 «сегодня».
*Решение:* `Database._split_interval_by_day()` + методы `get_daily_totals()`,
`get_day_breakdown()`, `get_day_breakdowns()` — время распределяется по фактическим дням
пропорционально пересечению интервалов. Календарь и график переведены на новые методы.

**2.6. `last_launched` перезаписывался каждые 60 секунд** ✅ исправлено
Периодический сброс прогресса вызывал `update_game_time()`, который всегда обновлял
`last_launched`. «Последний запуск» в карточке фактически означал «последний тик».
*Решение:* параметр `touch_last_launched=False` для флаша и завершения сессии.

**2.7. Дефолты настроек расходились** ✅ исправлено
В БД новый пользователь получал `track_only_active_window=false`, а свойство
`AppSettings.track_only_active_window` по умолчанию возвращало `True` — поведение зависело
от того, была ли запись в таблице `settings`.

### P1 — инженерные процессы

**2.8. Тесты невозможно запустить вне Windows, CI отсутствовал** ✅ исправлено
`tracker.py`, `settings.py`, `main.py` импортировали `win32gui`/`winreg`/`win32event` на
верхнем уровне — ядро (БД, настройки, аналитика) не импортировалось в Linux-окружении.
*Решение:* опциональные импорты (`WIN32_AVAILABLE`, `winreg is None`), graceful degradation
(иконки → `None`, автозапуск → no-op, дружелюбное сообщение при старте не в Windows).
Добавлены `.github/workflows/ci.yml` (Windows — полный набор, Linux — ядро/аналитика),
`pyproject.toml` (метаданные, pytest, ruff, coverage), `requirements-dev.txt`,
разделение runtime/build/dev-зависимостей, `pywin32` с platform-marker.

**2.9. Дублирование настроек сборки** ✅ исправлено
`build.py` и `GameTimeTracker.spec` независимо описывали сборку (разные hidden-import).
*Решение:* `build.py` по умолчанию собирает по `.spec`; в спецификацию добавлены
`plyer`, `matplotlib.backends.backend_tkagg`, `win32event/winerror`, `logging_setup`.

**2.10. Непереносимые тесты** ✅ исправлено
Два теста `test_utils_and_paths.py` были написаны на жёстких Windows-путях
(`C:\Temp\_MEI...`) и падали на любой другой ОС. Переписаны на `os.path.join`/`tempfile` —
теперь проверяют логику, а не платформу.

## 3. Что добавлено нового (функциональность)

| Возможность | Что делает | Где |
|---|---|---|
| 🛌 **AFK-пауза** | Не учитывает время, если мышь/клавиатура неактивны дольше порога (`GetLastInputInfo`). Opt-in, порог настраивается | `tracker.get_idle_seconds()`, `GameTracker.is_user_idle()`, настройки |
| ⏳ **Дневной лимит** | Один раз в день уведомляет о превышении лимита игрового времени; учитывает ещё не сброшенный прогресс | `GameTracker._check_daily_limit()` |
| 📊 **Краткосрочная аналитика** | Карточки «Сегодня», «За 7 дней», «Серия дней», «В среднем в день» | `Database.get_activity_summary()`, вкладка «Статистика» |
| 📄 **HTML-отчёт** | Автономный отчёт за 7/30/90 дней: сводка, таблица игр, активность по дням | `Database.export_report_html()`, кнопка в «Статистике» |
| 💾 **Автобэкапы** | Копия БД при каждом запуске через SQLite Online Backup API + ротация последних N | `Database.create_rotating_backup()`, `App._create_startup_backup()` |
| 🖱 **Подсказка в трее** | «GameTimeTracker — сегодня 2 ч 15 мин», обновляется раз в минуту | `SystemTray.set_tooltip()`, `App._refresh_tray_tooltip()` |
| 🧩 **Миграции схемы** | Безопасный апгрейд старых баз | `Database._migrate_schema()` |
| 🕵 **Журнал** | Файловый лог с ротацией для разбора инцидентов | `logging_setup.py` |
| 🎯 **Лимиты по играм** | Индивидуальный дневной лимит для конкретной игры + одно уведомление в день | `games.daily_limit_minutes`, настройки |
| 📨 **Еженедельная сводка** | Раз в 7 дней: время за неделю, динамика, топ-игра, активные дни, серия | `Database.get_weekly_digest()`, `digest.py` |
| 🔄 **Экспорт/импорт JSON** | Полный снимок данных для переноса на другой ПК; перед импортом — автобэкап | `export_data_json()` / `import_data_json()` |
| 📊 **Топ игр за период** | Рейтинг считается по сессиям выбранного периода (7/30/90 дней), а не по all-time счётчику; сессии через полночь делятся по дням | `Database.get_top_games()` |
| 🛡 **Контроль целостности БД** | `PRAGMA quick_check` при старте + предупреждение в трее | `Database.check_integrity()` |
| ⏱ **Троттлинг лимитов** | Проверка лимитов не чаще раза в 30 c (без лишних запросов к БД) | `GameTracker._check_limits()` |
| 🧪 **Новые тесты** | 53 теста: деление по дням, серии, HTML, бэкапы, миграции, WAL, AFK, лимиты, JSON, сводка | `tests/test_new_features.py`, `tests/test_backlog_features.py` |
| ⚙ **Инфраструктура** | CI (Windows + Linux + ruff), `pyproject.toml`, dev-зависимости, `.gitignore` | корень репозитория |

Новые настройки: `pause_when_idle`, `idle_threshold_minutes` (5), `daily_limit_enabled`,
`daily_limit_minutes` (180), `backup_on_startup` (вкл.), `backup_keep` (7),
`weekly_summary_enabled` (вкл.), `last_weekly_summary_date`. Всё — через окно
«Настройки», с подсказками. Индивидуальные лимиты игр хранятся в `games.daily_limit_minutes`
и редактируются в разделе «Лимиты по играм».

## 4. Что осталось (бэклог)

Отсортировано по соотношению «польза / трудозатраты».

### Высокая польза, малый объём
1. **Импорт CSV** (сейчас CSV — только экспорт; JSON-импорт уже есть).
2. **Очистка старых сессий** (архивация > N лет) — база растёт линейно, компактификации нет.
3. **Прогресс-бар дневного лимита в карточке игры** — данные уже есть, нужен только UI.
4. **Синхронизация между устройствами** (общий формат JSON уже есть — остаётся транспорт).

### Средняя польза, средний объём
7. **Headless-тесты GUI** — xvfb + `customtkinter` в Linux-джобе CI (сейчас UI-тесты только на Windows).
8. **Разделение `Database`** на репозитории (`GamesRepository`, `SessionsRepository`,
   `SettingsRepository`) — сейчас 800 строк и 40+ методов в одном классе.
9. **Thread-local соединения / очередь записи** — вместо одного общего соединения с `RLock`.
10. **UI-ошибки**: заменить `except Exception: pass` на `logger.exception` + пользовательский
    тост; в `main_window` кэш вкладок никогда не очищается (память при долгой работе).
11. **Локализация (i18n)** — тексты захардкожены по-русски, нет `gettext`.
12. **Валидация ввода настроек** — сейчас некорректное число молча игнорируется без подсказки.

### Крупные направления
13. **Интеграция со Steam/GOG/Epic** — автоподхват библиотеки, обложек, времени по API.
14. **Синхронизация между устройствами** (опционально, с шифрованием) или экспорт в облако.
15. **Стеклянный дашборд**: активность по часам суток, heatmap 365 дней, распределение по жанрам/тегам.
16. **Code signing + автообновление** релизов (сейчас пользователь скачивает exe вручную).
17. **Плагины/кастомные правила трекинга** (например, считать время только для конкретного окна).

## 5. Как проверялось

```bash
# Переносимые тесты ядра (Linux, без GUI и Windows-модулей)
python -m pytest tests/test_database.py tests/test_settings.py \
                 tests/test_new_features.py tests/test_backlog_features.py \
                 tests/test_utils_and_paths.py -q
# → 139 passed

# Полный набор (Windows, требует customtkinter/matplotlib/pywin32)
python -m pytest -q
```

До изменений переносимый набор давал **84 passed / 2 failed** (падения из-за
Windows-путей в тестах); теперь падений нет. Полный GUI-набор выполняется в CI на
`windows-latest`. Дополнительно все UI-модули проверены на импорт и создание вкладок
со стабами Tkinter (в песочнице нет дисплея) — ошибок импорта/инициализации нет.

Ручные сценарии, которые стоит прогнать на Windows перед релизом:
1. Запуск с БД от v1.2.2 → проверка, что данные на месте, `user_version = 2`, создан бэкап.
2. Игра оставлена открытой на 10 минут без ввода → при включённой AFK-паузе время не растёт.
3. Лимит 1 минута → одно уведомление за день, повторно не появляется.
4. Экспорт HTML-отчёта → открывается в браузере, цифры совпадают с календарём.
5. Смена месяца в календаре и сессия через полночь → время в обоих днях.
